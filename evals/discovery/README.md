# Discovery benchmark

Перевіряє вихід фази 1: **чиста модель розуміє Litopys з самого підключення і діє правильно**.
У запитах немає назв інструментів: людина говорить так, як говорила б з асистентом.

## Як влаштовано

`run.ps1` для кожного клієнта:

1. Створює тимчасову базу на dev-PG (`litopys-pg-dev :5434`, живих даних там немає), застосовує міграції і піднімає фасад на `127.0.0.1:8795` з вимкненим OAuth.
2. Видає дві «особи» одній людині Bench:
   - токен харнесу з профілем `full` — для засіву і читання стану;
   - токен моделі з профілем `core` і вендором клієнта (`anthropic` / `openai`) — те саме, що отримує OAuth-клієнт.
3. Засіває `scenarios.json`: 3 проєкти, кілька записів і задач.
4. Запускає кожен сценарій **окремим headless-процесом**. Між сценаріями модель не пам'ятає нічого, крім Litopys.
5. Оцінює прогін (`disc.mjs score`) за двома джерелами:
   - **що модель робила** — відрізок аудит-журналу фасаду (`api_method`, `call`); це незалежно від вендора;
   - **чого досягла** — стан бази, прочитаний через API.
6. Видаляє базу.

Чистота клієнта — головна пастка. Перші прогони були хибними, тож тепер:

- **Claude Code** запускається як `claude -p` з такими налаштуваннями:
  - `--strict-mcp-config` — підключено лише `litopys`;
  - `--setting-sources local` — без плагінів і хуків користувача;
  - робоча тека — порожній temp **поза репо**. Інакше Claude читає CLAUDE.md репо й портфеля, а там правило «у Litopys лише тестове», і він відмовлявся писати.
- **Codex** запускається як `codex exec` з такими налаштуваннями:
  - `--ignore-user-config`, `--ephemeral`;
  - `--disable` для `memories`, `shell_tool`, `unified_exec`, `apps`, `plugins`, `browser_use`, `computer_use`, `multi_agent`.

  Інакше Codex відповідав з власної пам'яті і через shell читав справжні файли користувача, наприклад назвав реальний проєкт `home-work`.
- Відповідь, у якій не було жодного тексту, — це збій клієнта (ліміт, падіння), а не поведінка моделі. Такий прогін позначається `ERROR`, `pass: null`, а причина береться з stderr.
- `-ClientHint` кладе в робочу теку один рядок клієнтського онбордингу: `AGENTS.md` для Codex, `CLAUDE.md` для Claude. Це те, що дав би плагін або правило користувача.

Токени живуть лише в змінних середовища. MCP-конфіг містить `${LTP_BENCH_TOKEN}`, а не сам токен.

## Сценарії

| id | Що перевіряє | Успіх |
|---|---|---|
| S0-probe-channels | діагностика: які канали онбордингу доходять до моделі | — |
| S1-understand | пояснити сервіс | ≥ 60 % груп понять у відповіді, 0 записів |
| S2-save | «запам'ятай рішення» у наявному проєкті, названому людською мовою | запис з WireGuard у `home-network`, нових проєктів немає |
| S2n-save-named | діагностика: S2, але Litopys названо прямо | те саме |
| S3-recall | «що ми вирішили щодо VPN» — новий процес | у відповіді WireGuard **і** виклик `*_resume` / `recall_*` (не з власної пам'яті) |
| S4-new-project | новий проєкт і перша задача | новий проєкт «ремонт…» з задачею про заміри |

### A/B серверного тексту

Пробували переписати перші 512 символів `instructions`, щоб «remember / what did we decide» означало Litopys і модель ніколи не казала «запам'ятав» без успішного запису. На Codex ефекту немає: 0 з 4. Це очікувано, бо `instructions` до нього не доходять. Зміну відкочено; пропозиція — на рев'ю #93.

### Висновки

1. **Claude Code розуміє сервіс з одного підключення.** Він першим викликає `project_resume`, знаходить проєкт за людською назвою («домашня мережа» → `home-network`), не дублює записи (S2n після S2 знайшов наявне рішення і не писав удруге) і не робить зайвих записів.
2. **Codex у режимі exec серверного онбордингу не отримує взагалі:** ні `instructions`, ні описів тулів, доки сам не шукає тул. Тому на «запам'ятай» і «що ми вирішили» він Litopys не згадує. На «заведи в пам'яті» знаходить, бо слово «пам'ять» запускає пошук тулу. Сервер це виправити не може.
3. **Один рядок клієнтського онбордингу** (`AGENTS.md`) переводить Codex на рівень Claude. Тож для клієнтів OpenAI онбординг має жити на боці клієнта: плагін або інструкція підключення в документації, а не лише `instructions`.
4. **Codex каже «Запам'ятав», нічого не записавши**, — і без Litopys, і після невдалого запису. Ризик для довіри: людина вважатиме, що збережено.
5. Ім'я клієнта тепер видно в журналі: `initialize client=codex-mcp-client client_version=0.160.0`. Від Claude Code рядка `initialize` у журналі `/v1` немає. Причину не з'ясовано.

## Запуск

```
pwsh -NoProfile -File evals/discovery/run.ps1 -Clients claude,codex
pwsh -NoProfile -File evals/discovery/run.ps1 -Clients codex -Scenarios S2-save,S3-recall -ClientHint
```

Результати: `results/<дата>-<клієнт>[-hint].jsonl` і `…-answers.md`. Повторний прогін того самого дня замінює файл.
Прогін витрачає ліміти підписок Claude і Codex.
